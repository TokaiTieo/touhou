# V13 日常生活与人物关系

## 设计边界

- 保留自然语言输入、开放地图、制作人工具及现有身材和后台恋爱资料。不以日常任务、关系数值或节日限制探索。
- 借鉴本地 eraTW 4.842 的机制组织，不复制其台词、人物数值或素材，不将改版私设作为官方设定。
- 使用 Conda `APITEST` 开发、测试与打包。当前源码为 v0.17.0；本轮没有重新构建 EXE 或 ZIP。

## 行动与结算

`action_resolution_service.py` 保守过滤引语、否定和未执行的计划；效果规则使用有效动作，而不是整段台词的关键词。该识别器不是通用语义理解，不能保证识别所有复杂句式。

六项日常活动由 `life_content.json` 配置：神社帮工、采集药材、魔法研究、制作便当、湖畔垂钓、制作小人偶。活动检查实际地点与材料，统一处理时间、疲劳、物品、报酬和成长。自然语言中的活动名称与 Vue 快捷入口使用同一结算函数；模型不能重复发放活动奖励。

前端日常命令使用既有操作回执和角色队列，重试复用 operation_id。活动、约定、关系回应与任务变化通过角色/任务联合事务保存，失败不提交半成品。旧接口不变。

## 人物与关系

日常计划按时间与工作地点推进，睡眠、外出暂停；已完成计划产生 NPC 自己的库存及可选后续事件，不直接发给玩家。离屏更新仍是轻量的六小时抽样模拟，不是每个 NPC 每分钟运行的完整生活仿真。

关系维度包含熟悉、信任、亲近、恋爱意愿和短期心情，与旧 score、stage 并存。高分不自动确立恋爱，但会结合主动/直率/含蓄性格、已确认共同经历和已有边界产生邀约或告白；恋人可以继续提出更长久的相伴。

玩家可以在“日常”中接受、暂不接受、保持朋友，也可以在选定人物的对话中明确回应。接受邀约不等于成为恋人，确认恋爱不等于同意其他亲密行为。现有成年校验及关系边界保持有效；制作人显式关系覆盖继续可用。

赠礼考虑已配置偏好、不喜、需求、品质、共同经历与当天重复衰减。普通玩家只看到从实际赠礼反应中了解到的偏好，不提前公开完整偏好答案。人物配置是可继续完善的游戏设计数据。

## 日历、事件与札记

- 邀约先为提议，NPC 根据已有熟悉程度及边界回应；确认后影响赴约时段的地点。支持改期、取消、到场与错过，不锁地图。当前回应是保守规则，不是复杂日程协商模型。
- 日历包含三个周期性日常节事；用于提供相聚时机，不是现实公历或完整四季系统。
- 事件区分发现、参与、完成、搁置。发现不解锁下一阶段；参与生成可选任务，完成绑定任务后再推进阶段。按钮不能直接凭空确认完成。
- 事件完成标记可来自已接受的任务结算；它不会把生成旁白直接提升为逐人事实记忆。通用事件的语义完成质量仍取决于原有任务结算，不是确定性的语义证明。
- 札记只从服务端结算记录生成，绑定持有人 NPC ID、参与者、地点、时间及来源。离屏私人札记不作为玩家已知事实公开；旁观者不自动获得共同经历。

## 存档迁移

V1-V12 加载时增量、幂等升级到 V13，沿用已有原始备份与迁移报告机制。新增 `life_state`、`relationship_dimensions` 和 `relationship_proposals`，当前版本的部分存档也补齐缺失默认字段。

已有关系原文和阶段保留；旧恋人标为旧关系已确认，不重新要求攻略。旧事件发现记录继续可参与，不猜测为已完成。未知字段、自定义人物、身材与恋爱资料、原始记忆以及纠错记录保留。

回档和分支恢复完整快照中的生活状态，不能把未来奖励和已接受的心意带回更早的时间线。正式旧档仅在玩家加载时升级，本次测试没有批量改写已有存档。

## 验证方式

- `npm run quality`：使用 APITEST，执行旧档兼容、动作过滤、关系回应、礼物偏好、事件、日历、实际计划、重复命令和快照分支测试。
- `node scripts/run-e2e.mjs`：隔离数据与模拟模型，验证 Vue 操作、刷新、地图自由及桌面/移动布局。
- 内容校验包含日常活动、节事、人物偏好与计划；制作人内容编辑器提供对应配置入口，发布配置包含内容 Schema。
- 未调用真实模型进行长回合质量验收，自动测试不能保证人物永远不认错人或剧情始终自然。
