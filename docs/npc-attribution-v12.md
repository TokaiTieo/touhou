# NPC 归属与记忆修复（v0.16.1 / V12）

## 已修复链路

历史输入曾只保留 speaker/content；自动记忆和人物计划又将玩家行动及生成旁白复制给在场人物。即使每个 NPC 独立存储，也会写入错误持有人。

- `history_context_service.py` 输出逐条 JSON 行，保留场景、说话者、NPC ID、参与者及可见范围；缺失项保持未知，不以当前对话人物补齐。
- `npc_attribution_service.py` 统一身份、逐人状态和明确互动对象。环境自由输入仅识别保守的明确称呼，单纯提到、否定或代词不自动产生个人事实；对话沿用玩家选定对象。
- `turn_orchestrator.py` 在状态写入前标记模型记忆提议；关系原因不再承载未经核实的生成事件。人物计划不因一句承诺就视作完成进展。
- `npc_memory_service.py` 区分持有人与事实主语，禁止待核实提议覆盖或被召回为事实；不删除正常的“A 记得 B 的事情”。
- 提示词的两层压缩、剧情摘要、消息改写及隔离评测沿用归属信息，前端不再重复上送没有元信息的历史窗口。

## 记忆来源

| 状态 | 行为 |
| --- | --- |
| `confirmed` | 来源明确的玩家表达、后端规则结算或制作人确认；玩家表达不代表其宣称的结果已经发生 |
| `pending` | 模型生成的记忆提议；保留供检查，不进入自动召回、事实冲突覆盖或压缩摘要 |
| `legacy_unverified` | 旧档原文；带未核实标记召回，不伪造参与者或重新认定事实主语 |

模型自行填写“system/direct”、高置信度或正确 ID，都不是事实主语正确的证明。此次采用保守方案，新增纯模型叙述需制作人确认后才能作为长期事实使用；近期对话仍保留叙事连续性。控制台原“新增/改写”按钮改为“确认/改写”。

## 兼容与纠错

V1-V11 自动迁移到 V12。迁移保留原文、自定义字段和原始备份；旧故事摘要另存原始副本，再由现有历史重建带归属的摘要。归档稳定标识不会因补充元信息改变。

明确纠错时，`npc_memory_corrections` 保存原记录及撤回标识，清理活跃/归档副本和派生缓存。没有可靠来源映射的旧摘要保留原文，但对应人物发生纠错后不再自动注入该旧摘要。回档和从快照创建分支会继承当前角色的纠错记录，无须修改历史快照或伪造其校验值。

未自动清洗真实玩家存档：目前没有经过人工核实的 TouHou 错误条目清单。独立导入纠错前导出包、丢失当前存档及全部纠错备份时，程序无法推断后来的修正。旧记录、生成旁白和无结构自由文本仍可能存在语义歧义；本修复不是“模型永远不会认错人”的保证。
