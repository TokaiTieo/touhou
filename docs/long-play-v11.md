# V11 长期游玩与评测说明

## 存档与恢复

- V1-V10 存档加载时先保留原始迁移备份，再增量升级为 V11。自定义资料、未知字段、角色身材与关系内容保留。
- 导入不设置文件大小上限。ID 仅作为文件名，危险 ID 自动生成安全新 ID，并保留来源；最终路径还需位于存档目录内。
- 高于当前 Schema 的存档不能被当前程序加载后改写、修复或覆盖导入，应升级程序后使用。
- 导入与快照恢复使用角色/任务联合事务。恢复前保留当前快照，损坏的原文件保留在 `_recovery`；回退创建新工作流 epoch，旧 checkpoint 不会复用到恢复后的时间线。

## 完整剧情档案

- 近期 `conversation_history` 保留 200-399 条消息，更早消息按 200 条写入 `_history/<sha256>.json`。这里的档案不是临时文件。
- 存档与快照中的 `conversation_archive` 只记录不可变分块及条目数。分块先落盘、引用随后随事务提交，失败事务可能留下无引用分块，但不会让旧存档出现新消息。
- 分支独立引用档案；评分、改写、删除旧消息时重新生成变化分块，不修改其他分支使用的旧分块。此隔离针对角色剧情与状态，不把共享世界内容编辑器变为分支编辑器。
- `/conversation_history` 支持 `before_id`、`limit` 和 `query`；AI 提示词继续使用近期窗口及摘要/记忆，不注入全部历史。
- 完整历史查找位于剧情区的“查找往事”。导出角色/反馈快照时合并原文；导入不接受缺少外部档案的单独内部存档文件。
- 手工备份必须包含完整数据目录；跨电脑推荐导出角色。已被旧版本截断且没有任何备份的历史无法恢复。

## 响应与性能

- `/character/{id}?view=state` 返回带 `response_version` 的当前状态；默认及 `view=full` 保留旧客户端的完整角色响应，便携迁移请使用导出接口。
- UI 状态刷新不再传输消息、向量索引和回执；制作人恢复操作的回执不嵌套完整存档。档案面板使用摘要视图，人物记忆组与历史诊断可分页读取。
- `npm run benchmark:saves` 在临时目录生成一千/一万条合成消息。数据量、消息长度、硬件会影响实测结果，不把本机延迟当作所有设备的承诺。

## 隔离评测

- 制作人控制台默认仍为 4 回合，可选 24 或 60。评测沿用生产提示词、记忆召回与结算流程，不写玩家存档、任务或 checkpoint。
- 覆盖灵梦、魔理沙、爱丽丝、帕秋莉，多地点日常、承诺、关系边界、带伤行动与搁置任务。场景切换由测试场景设置，不冒充地图移动正确性的证明。
- 运行前需人工确认。UTF-8 字节数作为保守输入预算，输出设置 `max_tokens`；评测调用禁用自动重试/模型回退，避免隐藏的重复费用。
- 可填写每百万 Token 的保守单价与费用上限，币种与服务商一致。无法获知实际用量时按预留预算估算；费用显示并非服务商账单，价格应由使用者核实。
- 达到预算、调用失败或收到停止请求后不再发起新回合。已经发出的调用仍可能产生费用，关闭控制台会请求停止后续回合。
- 文本评分属于启发式检查，状态/召回/关系边界属于程序断言，不能仅凭通过率证明长篇叙事质量。自动回归只运行模拟模型，真实质量需另行主动评测。
