# 可选 NPC 协作系统（v0.18.0 / V14）

## 发布范围

游戏设置提供 `legacy`（原流程）、`retrieval`（主持人检索增强）、`collaborative`（独立人物协作）三个模式，按角色保存。旧档自动补齐 V14 字段，默认仍为 `legacy`。切换模式不删除已发生的事件和人物记录；进行中的回合不能切换模式。

协作模式支持全部登记人物和有稳定 ID 的自定义人物，不是只为少数主角编写专属 agent。每回合最多六个不同 NPC，默认最多三个并发。同一回合不会用排队绕过人数限制，也不循环调用同一人物进行无限协商。超过限制、暂不在场或依赖尚未完成的互动保留待处理，玩家能看到尚未回应的人物。

只有明确的人物互动或相关待处理依赖才激活 NPC。仅在场、被提及、独自休息、界面停留和游戏关闭不触发 NPC 模型请求。离屏工作、计划和时间推进继续采用规则模拟。

## 五项职责

| 模块 | 责任与边界 |
| --- | --- |
| `agent_contracts.py` | 冻结读取者绑定、动作字段契约、调用上限；模型不能提交执行者 ID 或状态补丁 |
| `agent_context_service.py` | 五类只读证据查询，先做身份/时间线/可见性/事实状态过滤，再排序及分配预算 |
| `npc_agent_runtime.py` | 共享模型客户端、Functional API 子任务、SQLite 调用账本与恢复记录 |
| `agent_scheduler.py` | 0–6 人调度、依赖顺序、候选结算、主持人叙事和一次正式提交 |
| `agent_rules_service.py` | 本人命令校验、资源及日程冲突、事件去重和规则效果 |

正式游戏状态仍保存在原有角色/任务事务中；SQLite checkpoint 不是另一份 NPC 世界状态。实例绑定存档 ID、时间线 epoch、NPC ID、任务 ID 和权限版本。

## 权限与归属

统一查询为 `search_history`、`recall_npc_memory`、`search_world_info`、`get_task_context`、`get_npc_context`。读取者由服务器绑定，查询参数不能换人。查询结果携带来源和范围；召回使用统计只在成功候选提交时记录。

- NPC 可读自己的资料、状态、目标、库存、关系边界，以及本人合法持有的历史、记忆、札记和收到的事件。
- 相关性不授予权限。关于灵梦的记忆不自动向灵梦开放，魔理沙合法听闻灵梦的事也不会因出现他人姓名而被删除。
- `pending`、撤回、纠错和其他时间线记录不当作确定事实。听到某句话只证明发生过发言，不证明内容为真。
- 不同接收者的玩家原文分段保存，不能在后续自动记忆或人物活动记录中再次合并泄漏。旁观者不自动获得私密互动。
- 主持人的模型输入使用玩家可见发布视图。协调候选由代码掌握，不把 NPC 私人札记传给主持人再寄希望于提示词保密。
- 旧归属未知的代词不绑定当前人物。同名自定义人物使用 ID 隔离键，不共享旧姓名键的状态。
- 超长本人资料无法放入身份预算时明确中止，不静默删除身份后继续调用；玩家需要精简该人物的自定义资料。

### 2026-11-06 收件人边界修复

协作模式的显式指令按引号外的语句、连接词和收件人转向分段。例如“向甲问好。向乙私下说密码”与共同问好后的私语，只将对应片段交给各自人物。对话框选中的人物提供默认收件人，不绕过后续明确的收件人变化；动作和语言的现有封装格式继续支持。引号中的“向乙说……”属于发言内容，不重新激活乙。

只检查动作头的否定、计划与互动谓词，不用发言内容里的“不知道”否定已经发生的说话。朝人物方向移动不等于与其互动。名单残缺、同名没有唯一选择、无法确定的私语、未配对引号和同段多收件人歧义会在发送前要求澄清；该规则不是任意自由中文的语义证明，复杂转述应明确加引号并分句写出对象。

在场过滤先于六人截取，缺席人物不占名额。记忆所属人物、时间线及证据权限过滤先于向量化和排名，不只是截取后过滤。恢复指纹还包含代码上下文策略版本，升级后不沿用旧策略的人物结果或候选。

存档结构仍为 V14，不批量删除旧记忆、摘要或回滚记录；已发生的污染需依据明确来源逐条纠正，不能把合法传闻一并清除。源码专项及边界记录见 `reports/agent-boundaries-2026-11-06.md`；旧 EXE/ZIP 和旧真实评测不能作为该修复的发布或语义验收。

二次复查将代码上下文策略升级至3，并撤销“未知动作沿用上一受众”的兜底。未识别的动作只保留在玩家原始输入中，不发给任何NPC，不形成其收到该信息的记忆；不能将未分发解释成互动已执行。完整引语或“继续说：引语”等明确发言才可续接受众，未识别动作会断开继承。UI独立语言字段则保留自己的选择绑定，独自坐下或想了想不再取消其后的台词。需执行尚未识别的收件人句式时，应明确写为“向乙说……”或选中乙后在语言字段发言；这不增加探索解锁条件。

策略变更时，当前回合旧计划中不再使用的 `planned` 预留与新预留在同一事务内替换；已发送请求和未知费用不退回，也不修改其他回合。新计划仍超限时原子回滚。共享账本先启用WAL再启动并行任务，检查点初始化遭取消时关闭未注册连接。自动升级沿用原有V14流程，正式存档字段和费用历史不改写。

三次复查将上下文策略升级至4，修订上文独立语言的默认绑定：区分未指定（UI默认）、已明确指定和受众不明三种状态。“向乙私下说。想了想”之后的UI语言仍只给乙，不能回退甲；已确认的短暂停顿可保留明确绑定，未知动作则阻断该绑定，后续UI语言要求重新写明对象。无目标的独自行动和自言自语仍不激活人物。原始输入不会因此被批量改写，旧污染记忆仍需依据具体证据另行审计。

NPC对话请求中的 `is_continue` 默认为false，旧回合契约可直接读取。true时必须具有有效的当前NPC ID，以 `continue_dialogue` 任务意图继续已授权历史，不能由占位文本或其夹带的收件人改绑；控制信息不生成玩家发言记忆。Vue继续入口位于当前对话操作区，不受最后一条系统摘要影响，生成期间及结束对话后隐藏。

## 动作与回合提交

支持发言、邀约、接受、拒绝、改期、等待、本人计划、可接触对象调查、使用/提供/转交本人物品及本人关系提议。转交需接收方接受，最后一份物品不能被多个结果重复领取；NPC 不能替另一人同意约会。

旧日程提议接入同一事件入口；协作回合暂停旧流程的自动接受、主动关系决定及自动人物回应，防止双重执行。已有生活计划、日常活动、奖励、成长和状态规则继续运行。NPC 之间确认的约会到期由规则推进，私人札记不自动成为玩家共同经历。

流程为：快照 → 按身份准备上下文 → NPC 提案 → 规则合并及候选结算 → 主持人叙事 → 提交同一候选状态及历史回执。主持人失败后恢复复用已保存候选，不重算时间、奖励和物品。正式事务仍检查 revision，提交后清理子任务内容但保留费用账本。

**当前能力边界：**首版协作模式只为已实现的规则活动、已知地点和上述领域命令提供确定性状态变化；任意自由文本任务完成、新地点创造等尚未与旧主持人流程全面等价。地图不加探索解锁条件，但这不等于所有自由叙事都自动产生规则效果。复杂反复谈判暂不支持，因此保持可选，不替代原流程。

## 叙事与显示

用户选择保留自由叙事。NPC 的已验证决定作为独立消息原文展示，并标为“本人回应”；旁白不能通过字段修改 NPC 的正式决定。NPC 规范消息禁止单独重写，以免伪造本人决定。

审计记录规范事件 ID、引用合法性、叙事哈希及 `semantic_consistency: unverified`。这不是自然语言语义证明：旁白仍可能在文字上认错人、复述错误或与决定冲突。多个 agent 同意同一说法也不能证明事实成立。

引用集合由后端从本回合玩家可见事件绑定，在模型子任务内校验后才标记成功；空事件回合只能引用空列表。非法引用产生失败检查点和失败计费，手动恢复重新生成主持人，不自动重试，不重复候选结算。主持人结果策略版本2单独进入任务／计费键，避免复用旧策略的错误成功缓存；相同上下文下不因此废弃有效NPC结果。若同时发生本轮上下文策略3→4升级、权限或状态变化，则相关NPC和候选仍必须重新生成，不能以减少费用为由复用不再可信的结果。

## 预算与恢复

默认每回合最多 10 次模型请求、500,000 Token 的保守预算、240 秒总时限；每次输出最多 1,800 Token。并发默认 3，参与人数上限固定 6。额度在发送前覆盖必需人物及最终叙事，额外依赖、失败和手动重试都计入账本。

已完成子任务、证据、输入指纹、revision、epoch、权限版本、候选及用量可恢复。任一相关事实/权限/状态变化都会改变任务指纹，使旧结果失效。无法得知实际消耗的超时/取消请求保留保守预留，不假定免费。

断线后仅查询状态，不自动另发付费请求；刷新亦不会静默重试。玩家明确选择“恢复本回合”才继续未完成工作。关键人物失败则整个回合待恢复，不由主持人代答；取消后的迟到响应不能提交。

官方 DeepSeek V4/Flash 结构化调用显式关闭 thinking 并请求 JSON，避免默认思考占满短输出预算；不擅自向自定义代理附加供应商专有参数。依据：[Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)、[JSON Output](https://api-docs.deepseek.com/guides/json_mode/)。格式输出仍须校验，不保证模型永不返回错误字段。

## 旧档兼容

V1–V13 通过既有增量迁移升级 V14；补入 `agent_state` 默认值并保留原始备份、剧情摘要备份、未知字段、身材和恋爱资料。当前版缺失默认字段也会补齐。自定义资料不会因升级改写。

快照、分支、导出及导入包含模式和事件。分支为保留下来的合法历史重绑定新 epoch，并保留来源 epoch；旧结果、未来事件和别的时间线不因此获得权限。既有纠错继承机制保留。恢复测试和真实评测均使用临时/合成角色，没有批量改写正式存档。

## 验证与评测

专项测试见 `test_agent_context.py`、`test_agent_runtime.py`、`test_agent_scheduler.py`、`test_agent_boundaries.py`、`test_agent_recovery.py`、`test_agent_persistence.py`；浏览器用例为 `e2e/agents.spec.mjs`。10-30 发布 EXE 曾验证同一协作回合重复提交不重复调用，后续源码修改需重新构建验证。

真实三模式脚本为 `scripts/evaluate-agents.py`。用户授权的 **5,000,000 Token 是所有模式、阶段、失败与复测的合计上限**。报告、逐次合成请求和统一账本位于 `reports/agent-evaluation-2026-10-29/`，不进入分发包。

对照基线是当前兼容模式，不是历史 v0.17 二进制。三模式使用相同合成初始存档、动作和输出限制；长期测试包含失败尝试，不能把 60 次尝试写成 60 次成功。固定场景临时安排人物同场，因此不能据此证明全部自然移动路线的体验质量。

结构隔离、调用数、延迟、Token 可自动核验；人物口吻、事实承接、自由度、节奏和关系自然度仍需阅读记录和人工验收。启发式评分不是人工评分，也不是防串写的语义证明。最终数字与未完成项见 `docs/project-governor.md` 和评测报告，不根据文档标题推定全部通过。
